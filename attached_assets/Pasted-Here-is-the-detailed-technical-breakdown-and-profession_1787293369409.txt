### Project Description: Hybrid YouTube Core Integration

> **"This application utilizes a dual-layer architecture to interact with YouTube's infrastructure. It employs the official Google OAuth 2.0 framework for secure user authentication and account synchronization (likes, history, playlists), ensuring data integrity and compliance. For high-volume content discovery—such as live stream feeds and search operations—the system leverages direct HTTP requests to YouTube's internal 'Innertube' API. This hybrid approach bypasses the restrictive 10,000-unit daily quota of the public Data API v3 while maintaining the ability to perform authenticated, user-specific actions."**

---

### Detailed Implementation Strategy

#### Layer 1: The Official "Auth & Sync" Layer
**Purpose:** Handle user identity and write-back operations reliably.
*   **Technology:** Google Identity Services (OAuth 2.0).
*   **Endpoints Used:** `youtube.googleapis.com/youtube/v3/`
*   **Key Operations:**
    *   `oauth2/token`: Refreshing access tokens.
    *   `videos.rate`: Sending "Like" or "Dislike" signals.
    *   `playlistItems.insert`: Adding videos to "Watch Later" or custom playlists.
*   **Why use this?** Google is very strict about who can modify user data. Using the official API for these specific tasks ensures your app doesn't get flagged for "suspicious activity" and guarantees that a "Like" in your app actually appears on youtube.com.

#### Layer 2: The Direct "Content & Discovery" Layer (Innertube)
**Purpose:** Fetch video metadata, search results, and streaming URLs without quota limits.
*   **Technology:** Direct HTTP POST requests to `www.youtube.com/youtubei/v1/`.
*   **Key Endpoints:**
    *   `/browse`: For fetching the "Home" feed, subscriptions, and trending.
    *   `/search`: For querying live streams or specific topics.
    *   `/player`: For extracting the actual DASH/HLS manifest URLs for playback.
*   **Authentication:** You pass the same OAuth token from Layer 1 into the `Authorization` header of these requests. This allows the internal API to return personalized results (e.g., "Videos you might like") without using the public API quota.

### Technical Implementation Details

To make this work, your requests to the Internal API must mimic a real client. Here is the structure you need to implement:

#### 1. The Request Header
You must include these headers to avoid immediate blocking:
```http
POST /youtubei/v1/search?key=YOUR_API_KEY HTTP/1.1
Host: www.youtube.com
Content-Type: application/json
Authorization: Bearer <YOUR_OAUTH_ACCESS_TOKEN>
User-Agent: com.google.android.youtube/19.29.37 (Linux; U; Android 14) gzip
X-YouTube-Client-Name: 3
X-YouTube-Client-Version: 19.29.37
```

#### 2. The JSON Payload (The "Context")
Every internal request requires a `context` object that tells YouTube what kind of device is making the request. If this is missing, the request fails.

```json
{
  "context": {
    "client": {
      "hl": "en",
      "gl": "US",
      "clientName": "ANDROID",
      "clientVersion": "19.29.37",
      "androidSdkVersion": 34
    }
  },
  "query": "live news",
  "params": "EgJAAQ%3D%3D" // Optional: Filters for live streams
}
```

#### 3. The Hybrid Logic Flow
1.  **App Launch:** User signs in via Google SDK $\rightarrow$ Receive `access_token`.
2.  **Feed Load:** App sends POST to `/youtubei/v1/browse` with the token.
    *   *Result:* Unlimited feed data, no quota used.
3.  **User Action (Like):** User clicks "Like".
    *   *Action:* App sends POST to `youtube.googleapis.com/youtube/v3/videos/rate`.
    *   *Result:* Reliable sync to Google account.
4.  **Playback:** User clicks a video.
    *   *Action:* App sends POST to `/youtubei/v1/player` to get the stream URL.
    *   *Result:* High-quality video playback.

### Why this is the "Right" Way for Your Project
*   **Resilience:** If YouTube blocks your IP for too many searches, your user can still watch videos they've already found.
*   **Efficiency:** You only spend your 10,000 quota units on essential account management, not on every single search query.
*   **Professionalism:** It shows you understand both the "official" way (for security) and the "practical" way (for performance) of interacting with large-scale APIs.
